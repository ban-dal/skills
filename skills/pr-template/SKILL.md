# PR Template

PR 형식보다 사실성을 우선한다. 저장소의 기여 규칙과 PR 템플릿이 있으면 그것을 사용하고,
없을 때만 이 스킬의 기본 구조를 적용한다.

## 근거를 수집한다

base와 head를 확정한 뒤 다음을 확인한다.

```bash
git status --short
git branch --show-current
git log --oneline <base>..HEAD
git diff --stat <base>...HEAD
git diff --check <base>...HEAD
```

- 커밋, 변경 파일, 테스트 결과, 브랜치 이름을 추측하지 않는다.
- 사용자가 지정한 base를 우선한다. 지정이 없으면 PR·브랜치·remote 기본 브랜치와 저장소
  문서에서 근거를 찾는다.
- 실제 PR을 만들 때도 base를 신뢰성 있게 결정할 수 없으면 사용자에게 확인한다.
- dirty worktree에서는 관련 파일만 명시적으로 스테이징한다. 사용자의 다른 변경을 섞지 않는다.
- 커밋 전 staged diff와 `git diff --cached --check`를 확인한다.
- 실행한 검증만 성공으로 표시한다. 훅의 부분 검증을 전체 검증으로 표현하지 않는다.

## 저장소 형식을 우선한다

`CONTRIBUTING.md`, `AGENTS.md`, `.github/pull_request_template.md`와 GitHub의 다중 PR
템플릿을 확인한다. 제목 규칙과 필수 섹션을 포함해 저장소 규칙이 이 스킬의 기본값보다 우선한다.

저장소 형식이 없으면 다음 구조를 작업에 맞게 사용한다.

```markdown
## 개요

- 변경 목적과 사용자 가치를 1~2개 항목으로 설명합니다.

## 변경 사항

- 실제 diff로 확인되는 동작·구조·정책·테스트 변경을 적습니다.

## 검증

- [x] `<성공한 명령>`
- [ ] `<실행하지 못한 검증>`
  - 이유와 확인된 대체 범위

## 리뷰 포인트

1. 리뷰어가 판단해야 할 경계나 트레이드오프를 적습니다.

## 후속 작업

- 이번 PR 범위 밖의 작업이 있을 때만 적습니다.
```

해당 내용이 없는 선택 섹션은 생략한다. 저장소 템플릿이 빈 섹션 유지를 요구하면 유지한다.
UI 변경에는 업로드 가능한 스크린샷이 있을 때만 링크하고, 로컬 경로를 GitHub 링크처럼
작성하지 않는다.

## 내용을 대조한다

- 모든 커밋 해시는 실제 `<base>..HEAD` 범위에 있어야 한다.
- 변경 설명은 diff 또는 커밋으로 증명되어야 한다.
- 검증 체크 상태는 실행 로그와 일치해야 한다.
- 미완료·제외 범위를 완료된 것처럼 표현하지 않는다.
- 리뷰 포인트는 변경 사항을 반복하지 않고 판단이 필요한 내용에 집중한다.
- 커밋과 PR 본문에 불필요한 생성 도구 표식을 추가하지 않는다.

## 요청한 범위만 실행한다

- PR 메시지만 요청하면 제목과 본문만 작성한다.
- 커밋을 요청하면 관련 파일만 작업 단위로 스테이징하고 검증한 뒤 커밋한다.
- PR 생성을 명시적으로 요청한 경우에만 push와 PR 생성을 수행한다.
- 실제 PR 생성 시 base와 head를 모두 명시한다.

제목은 저장소 규칙을 따른다. 별도 규칙이 없으면 `<type>: <요약>` 형식과 변경 성격에 맞는
`feat`, `fix`, `chore`, `refactor`, `docs`, `test`, `ci`, `perf`, `build` 중 하나를
기본값으로 사용한다.
