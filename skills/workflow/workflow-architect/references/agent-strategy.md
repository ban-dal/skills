# 의존성·병렬·Agent 전략

병렬은 목적이 아니라 결과다. Agent를 많이 만드는 것이 아니라, 먼저 의존성을 분류한다.

## 의존성 분류

- **병렬 가능** — 선행 의존성이 없고, 파일 범위가 서로 겹치지 않는다.
- **순차 필수** — 한 Task의 출력이 다른 Task의 입력이다.
- **머지 후** — 공유 인터페이스·설정·라우팅 등 통합 지점을 만지는 작업. 병렬 작업이 끝난 뒤 단독으로 수행한다.

## Agent 규칙 (환경 무관)

> **한 Agent = 하나의 파일 범위 + 하나의 책임.** 두 Agent가 같은 파일을 쓰지 않는다.

- **Claude Code** — sub-agent를 병렬로 띄워 파일 범위별로 분배한다.
- **Codex / Cursor / 수동** — 같은 Task 경계를 순차 세션 또는 사람 분배로 실행한다. 경계와 파일 범위는 그대로 유효하다.

병렬 가능 판단은 다음을 모두 만족할 때만 "예"다:

- Task 간 의존성이 낮다.
- 수정 파일 충돌 가능성이 낮다.
- 각 Agent의 책임이 명확하다.
- 각 Agent 결과를 독립적으로 검증할 수 있다.
- Merge 이후 통합 검증이 가능하다.

하나라도 어긋나면 병렬을 포기하고 순차로 강등하거나 Task를 다시 쪼갠다.

## Agent Task Card

병렬 작업마다 아래 7필드를 채운다. 빈 칸이 있으면 그 Agent는 아직 병렬에 투입할 수 없다.

```
목적          — 이 Agent가 끝내야 할 한 가지
입력          — 시작 시 주어지는 것(파일·계약·전제)
수정 가능 범위 — 건드려도 되는 파일/디렉터리
수정 금지 범위 — 절대 건드리면 안 되는 것(다른 Agent 소유)
완료 조건      — 체크 가능한 종료 기준
검증 방법      — 완료를 어떻게 확인하는가
예상 산출물    — 끝났을 때 남는 것(PR·파일·변경)
```
