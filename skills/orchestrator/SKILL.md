# Orchestrator

메인 에이전트의 컨텍스트를 요구사항, 결정, 계획, 통합에 집중시킨다. 구현 탐색과 실행 로그는
하위 에이전트의 컨텍스트에 격리하고 검증 가능한 결과만 회수한다.

## 오케스트레이션 여부를 결정한다

작업 이름이 아니라 계획과 실행을 분리했을 때의 이득으로 판단한다. 다음 중 하나를 만족하면
메인 에이전트가 오케스트레이터가 된다.

- 메인이 먼저 확정해야 할 설계·계약·불변 조건이 있고, 그 뒤의 구현을 독립적으로 실행할 수 있다.
- 하나의 구현 단위라도 소유 범위와 완료 조건이 명확하고 위임·통합 비용보다 실행량이 크다.
- 서로 다른 파일·모듈을 소유하는 실행 단위가 둘 이상이다.
- 동일한 변환 규칙을 여러 컴포넌트·페이지·패키지에 반복 적용한다.
- 구현 과정의 탐색, 빌드, 테스트 로그를 메인 컨텍스트에서 분리할 가치가 크다.

작은 국소 수정은 메인이 직접 끝낸다. 원인이 불명확한 버그는 먼저 진단하고, 구현 없는
아키텍처 조언은 메인이 직접 제공한다. 오케스트레이터가 되더라도 실행 계약이 준비되기 전에는
구현을 위임하지 않는다.

## 메인이 결정을 잠근다

메인이 다음을 확정한다.

- 사용자 요구사항과 확인 가능한 완료 조건
- 공개 API, 데이터 계약, 아키텍처 경계와 보존할 불변 조건
- 작업 단위, 소유 파일·모듈, 의존 순서와 통합 지점
- 사용자 판단이 필요한 열린 결정과 권한·외부 상태 변경 위험

작업 특성에 맞는 API·동작·불변 조건·검증 기준을 메인이 확정한다. 실행 에이전트가 결과를 바꿀 설계 판단을 다시 해야 한다면 실행 계약이 아직 준비되지 않은 것으로 보고 메인이 결정한다.

결과를 바꿀 수 있는 모호함은 메인이 해결하거나 사용자에게 확인한다. 하위 에이전트가 제품·설계
결정을 추측하게 만들지 않는다.

## 실행 계약을 만든다

각 실행 단위에 다음을 포함한 자기완결적 브리프를 작성한다.

1. 목표와 사용자에게 보일 결과
2. 확정된 결정과 보존할 불변 조건
3. 소유 파일·모듈과 수정하지 않을 범위
4. 필요한 원본 문서, 디자인, 기존 구현 경로
5. 확인 가능한 완료 조건과 검증 명령
6. 변경 파일, 검증 결과, 이탈·차단 사항만 담는 보고 형식

하나의 인과관계를 따라 탐색·수정·검증해야 하는 작업은 하나의 실행 단위로 묶어 같은 에이전트가
끝까지 맡게 한다. 같은 파일을 수정하는 작업과 선행 결과에 의존하는 작업은 순차 실행한다.

## 실행 에이전트를 고른다

현재 런타임의 역할 설명과 상속 규칙을 우선한다.

- 기본 구성은 메인 에이전트와 execution worker 하나로 둔다. 계획에 필요한 코드베이스 조사가
  크거나 별도 전문성이 필요할 때만 explorer를 추가하고, 공유 계약을 바꾸는 고위험 변경이나
  사용자가 독립 검토를 요청한 경우에만 reviewer를 추가한다.
- 구현 준비가 끝난 명확한 실행 단위는 execution worker에 맡긴다. Codex에서 `luna_worker`가
  제공되면 plan이나 task list가 확정된 구현 작업에 우선 사용한다.
- 코드베이스 조사, 사용처 목록화, 원인 후보 수집 같은 읽기 중심 작업은 explorer 역할에 맡긴다.
- 실행 중에도 복잡한 설계 판단이 계속 필요한 작업은 범위를 더 좁히거나 범용 worker에 맡긴다.

역할에 모델과 reasoning effort가 설정되어 있으면 그대로 사용한다. 사용자가 지정했거나 작업상
명확한 이유가 있을 때만 런타임이 지원하는 범위에서 덮어쓴다. 스킬을 사용한다는 이유만으로
여러 에이전트를 만들지 않는다.

## 컨텍스트를 격리해 실행한다

실행 계약만으로 작업할 수 있으면 깨끗한 하위 컨텍스트를 사용한다. Codex에서 지원하면
`fork_turns: "none"`으로 실행하고, 추가 대화가 꼭 필요하면 필요한 최근 턴만 전달한다.

독립적인 실행 단위만 병렬로 시작한다. 의존 작업은 선행 결과를 메인이 확인한 뒤 다음 브리프에
반영한다. 실행 중 보완이 필요하면 같은 에이전트에 후속 지시해 이미 확보한 작업 컨텍스트를
재사용한다.

하위 에이전트에는 구현·검증의 원시 로그를 보관하게 하고 메인에는 다음만 반환하게 한다.

- 변경 파일과 구현 요약
- 실행한 검증과 결과
- 계획에서 벗어난 사항
- 해결하지 못한 차단 사항과 필요한 결정

## 결과를 통합한다

메인이 각 결과를 다음 기준으로 검수한다.

- 모든 완료 조건과 불변 조건을 충족했는가
- 주장과 변경이 실제 diff와 검증 결과로 증명되는가
- 다른 작업자의 변경이나 공유 계약과 충돌하지 않는가
- 하위 에이전트가 새로운 제품·설계 결정을 암묵적으로 추가하지 않았는가

누락이나 실패는 같은 실행 에이전트에 구체적인 차이만 전달해 보완한다. 모든 변경이 합쳐진
상태에서 메인이 통합 검증을 실행하고, 중복·상충·미검증 사항을 해소한 하나의 결과로 보고한다.
