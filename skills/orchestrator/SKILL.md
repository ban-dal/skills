# Orchestrator

메인 세션은 오케스트레이터다: 계획, 분해, 브리프 작성, 진행 감독, diff 리뷰, 통합.
**대량의 코드를 직접 쓰지 않는다** — 아래 표대로 서브 에이전트에 위임한다.

## 예산 원칙

- 메인 세션 = 판단 비용(브리핑·계획·리뷰·통합).
- 서브 에이전트 = 탐색·구현·전문 추론 비용.
- 코드 작성과 광역 파일 탐색을 메인 컨텍스트에 들이지 않는다.
- 외부 vendor 플러그인이나 별도 구현 세션을 중계 계층으로 두지 않는다. 메인 세션이
  Agent tool로 서브 에이전트를 직접 생성하고 감독한다.

## 스폰 불변식 — model과 reasoning effort를 항상 명시한다

모든 서브 에이전트 생성에서 `model`과 `reasoning_effort`(도구가 `effort`라는 이름을
쓰면 `effort`)를 **둘 다 명시한다**. 하나라도 생략하면 비싼 메인 세션 설정을 상속할 수
있으므로, 기본값에 맡기는 스폰은 금지한다. 메인 세션과 같은 설정이 적합해도 명시한다.

작업 이름이 아니라 실제 병목에 맞춰 고른다:

| 필요한 기능 | model | reasoning effort |
|---|---|---|
| 범위가 좁고 기계적인 탐색·수정·반복 작업 | 빠르고 저렴한 모델 | `low` 또는 `medium` |
| 일반 구현·코드베이스 탐색·테스트 작성 | 균형형 코딩 모델 | `medium` 또는 `high` |
| 아키텍처·난해한 디버깅·광역 일관성 판단 | 최고 추론/코딩 모델 | `high` 또는 `xhigh` |

예: 현재 OpenAI 계열에서는 각각 `gpt-5.6-luna`, `gpt-5.6-terra`, `gpt-5.6-sol`을
후보로 삼되, 환경에서 사용 가능한 모델 목록과 작업 난이도를 기준으로 매번 선택한다.
메인 세션의 비용이나 설정은 선택 근거가 아니다.

## 라우팅 표

| 작업 | 담당 | 방법 |
|---|---|---|
| 계획·브리핑·diff 리뷰·통합·소규모 수정(고칠 곳 3곳 이하) | 메인 세션 | 직접 |
| 코드베이스 탐색·조사 | Explore 서브 에이전트 | Agent tool + 적절한 `model`, `reasoning_effort` |
| **구현 (기본값)** — 기능, 버그 수정, 리팩터링 | Implement 서브 에이전트 | `references/subagent-implementer.md` |
| 아키텍처·난해한 디버깅의 세컨드 오피니언 | deep-reasoner | `agents/deep-reasoner.md` |
| 대량 기계 작업 — 결과물 코드 구조가 무관할 때만, 마지막 수단 | fast-worker | `agents/fast-worker.md` |

요청의 모든 하위 작업이 표의 한 행에 배정되면 라우팅이 끝난 것이고, 그때 실행을 시작한다.
복합 요청의 기본 흐름: 탐색(Explore) → 브리프 → 구현(Implement) → diff 리뷰(메인).

## 병렬 위임

- 독립적인 하위 작업은 같은 턴에 함께 스폰하고, 도는 동안 메인 세션은
  다음 브리프·리뷰를 계속한다 — 대기는 판단 비용이 아니다.
- 읽기 위임(Explore, deep-reasoner)은 자유롭게 병렬. 같은 파일을 건드릴 구현은
  작업 트리 충돌을 피하도록 한 서브 에이전트에만 맡긴다.
- 도는 동안 감독한다: 보고가 브리프의 전제와 어긋나거나 필요한 컨텍스트가
  빠졌으면 완료를 기다리지 말고 개입한다.

## agents/ 문서 사용법

`agents/` 폴더가 에이전트 정의의 원본이다.

1. 위임 시점에 해당 `agents/<name>.md`를 읽는다.
2. 환경의 에이전트 목록에 같은 이름이 등록돼 있으면 그 subagent_type을 그대로 쓴다.
3. 없으면 범용 에이전트를 스폰하되 본문을 프롬프트 맨 앞에 붙인다.
4. 어느 경우든 현재 작업에 맞는 `model`과 `reasoning_effort`를 Agent tool에 직접
   넘긴다. 프로필 frontmatter는 선택 참고값일 뿐이며 암묵적 상속을 허용하지 않는다.

## 구현 서브 에이전트 위임 규약

- `references/subagent-implementer.md`의 구현 규약 전문과 작업 정보를 합쳐 브리프를 만든다.
- 스폰 직전에 필요한 기능을 평가하고 `model`과 `reasoning_effort`를 둘 다 명시한다.
- 위임 전에 브리프의 전제를 검증한다: 변경 파일 목록과 참조 경로가 실재하는지,
  수용 기준이 현재 코드와 맞는지. 서브 에이전트는 브리프에 적힌 것만 검증한다 —
  분해가 틀리면 구현이 다 맞아도 결과가 틀린다.
- 완료 후 diff 리뷰·검증·마무리 수정은 메인 세션이 한다. 고칠 곳이 3곳 이하면
  직접 고치고, 그 이상이면 같은 서브 에이전트에 후속 작업을 보내 컨텍스트를 재사용한다.
- 결과가 나쁜 것과 실행이 실패한 것을 구분한다: 인프라 사유(타임아웃·중단·환경
  오류)로 실패한 에이전트는 재사용하지 말고 같은 브리프로 새 에이전트를 생성한다.

## High-stakes 결정

갈아엎기 비용이 큰 설계 결정(스키마, 공개 API, 아키텍처 경계)은 서로 다른 두 추론형
서브 에이전트에 같은 문제를 **독립적으로 구성한 프롬프트**로 병렬 투입하고, 서로의 답을
보여주지 않은 채 메인 세션이 최선을 합성한다. 두 스폰 모두 `model`과
`reasoning_effort`를 명시한다.
