# Orchestrator

여러 에이전트를 쓰는 것이 이미 결정되었을 때 협업 손실을 줄인다. 현재 환경이 위임을
지원하고 사용자의 요청 범위가 허용할 때만 사용한다.

## 위임할 작업을 고른다

다음 조건을 만족하는 하위 작업만 분리한다.

- 다른 작업과 독립적으로 진행하거나 검토할 수 있다.
- 소유 파일·모듈 또는 읽기 전용 산출물이 명확하다.
- 결과를 객관적으로 검증하고 메인 작업에 통합할 수 있다.
- 브리프 작성과 결과 통합 비용보다 병렬성·전문성·독립성의 이득이 크다.

하나의 인과관계를 따라 탐색·수정·검증해야 하는 작업은 같은 에이전트가 끝까지 맡는다.
같은 파일을 수정하는 작업은 병렬화하지 않는다.

## 브리프를 자기완결적으로 만든다

각 작업에 다음을 제공한다.

1. 목표와 확인 가능한 완료 조건
2. 소유 범위와 수정하면 안 되는 범위
3. 필요한 원본 문서와 기존 구현 경로
4. 이미 결정된 사항과 아직 열려 있는 사항
5. 실행할 검증 명령 또는 필요한 보고 형식

작업에 필요하지 않은 대화 기록이나 예상 결론은 전달하지 않는다. 독립 검토에는 다른
에이전트의 결론을 보여주지 않는다.

## 실행 방식을 환경에 맞춘다

현재 런타임이 제공하는 에이전트와 기본 상속 규칙을 우선한다. 모델·reasoning effort는
사용자가 지정했거나 작업상 명확한 이유가 있고 도구가 지원할 때만 덮어쓴다. 특정 공급자의
모델 이름이나 고정된 비용 등급을 스킬 규칙으로 가정하지 않는다.

독립적인 작업은 병렬로 실행하고, 의존 작업은 선행 결과를 확인한 뒤 전달한다. 새 worktree나
외부 상태 변경은 사용자 요청 또는 실제 파일 충돌처럼 구체적인 필요가 있을 때만 사용한다.

## 결과를 통합한다

각 결과에서 다음을 확인한다.

- 완료 조건을 충족했는가
- 주장과 변경이 실제 파일·diff·실행 로그로 증명되는가
- 다른 작업자의 변경과 충돌하거나 전제를 깨뜨리지 않는가
- 실패·미검증·열린 결정이 명시되었는가

보고서를 단순 연결하지 않는다. 중복을 제거하고, 상충하는 결론은 근거를 비교해 해소하며,
전체 작업의 위험도와 우선순위로 다시 정리한다. 변경 작업은 통합된 상태에서 최종 검증한다.
