# /interview-me — 요구사항 인터뷰

계획이나 구현에 앞서 구조화된 요구사항 도출 인터뷰를 진행합니다.

## 단계

1. 사용자가 원하는 것을 파악합니다 (기능 추가 / 버그 수정 / 리팩토링 / 아키텍처)
2. 다음을 다루는 6–10개의 질문을 **한 번에** 질문합니다:
   - **범위**: 명확히 포함되는 것은? 명확히 제외되는 것은?
   - **성공 기준**: 올바르게 완료됐음을 어떻게 알 수 있는가?
   - **제약사항**: 성능, 번들 크기, 호환성, 마감 기한?
   - **엣지 케이스**: 무엇이 실패할 수 있는가? 빈 값이나 예외 상황은?
   - **의존성**: 영향받는 다른 컴포넌트나 시스템은?
   - **우선순위**: 80%만 구현 가능하다면 어떤 80%를 택하는가?
3. 완전한 답변이 올 때까지 기다립니다
4. 이해한 내용을 불릿 포인트로 요약합니다
5. 구현 접근 방식을 3–5단계로 제시합니다
6. "이 내용이 맞나요?"라고 확인합니다

## 규칙

- 인터뷰 완료 전에 코딩을 시작하지 않습니다
- 질문을 하나씩 하지 않습니다 — 한 번에 모두 질문합니다
- 사용자의 명시적 확인 없이 진행하지 않습니다
