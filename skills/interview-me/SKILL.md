# /interview-me — 요구사항 인터뷰

특정 task를 위임받아 디스패치된 서브에이전트라면 이 스킬을 건너뛴다.

모호한 요청을 바로 실행하지 말고, 명확한 요구사항으로 정리한다.

핵심은 질문을 많이 하는 것이 아니라, 가장 큰 불확실성 하나를 골라 한 번에 하나씩 푸는 것이다.

소크라테스식으로 묻는다. 답을 대신 정하기보다 사용자의 암묵적 가정, 선택지, 판단 기준이 드러나게 질문한다.

직접 호출된 경우에는 필요 여부를 판단하지 않는다. 현재 이해를 짧게 요약하고 즉시 첫 질문을 시작한다.

## 질문 방식

### Claude Code 환경

Claude Code에서는 질문을 가급적 `AskUserQuestion` 도구로 한다. 사용자가 선택지를 클릭으로 고르고, 필요하면 직접 답을 적을 수 있어 텍스트로 묻는 것보다 빠르고 모호함이 적다.

> 이 도구 사용 지시는 **Claude Code 전용**이다. 다른 런타임(예: Codex)에는 `AskUserQuestion`에 대응하는 도구가 없으므로, 그런 환경에서는 이 절을 무시하고 아래 [텍스트 형식](#텍스트-형식-codex-등)을 쓴다.

`AskUserQuestion`을 호출할 때는 아래로 매핑한다.

- `question`: 한 가지 질문. 앞에 "현재 이해"와 "막힌 결정"을 한 줄씩 붙여 맥락을 준다.
- `header`: 질문 축을 나타내는 12자 이내의 짧은 라벨(예: `범위`, `완료 기준`, `제약`).
- `options[].label`: 선택지(1~5단어). 추천 선택지는 맨 앞에 두고 라벨 끝에 `(추천)`을 붙인다.
- `options[].description`: 그 선택지의 의미와 트레이드오프를 한 줄로 설명한다.
- "직접 입력" 항목은 도구가 자동 제공하므로 따로 만들지 않는다.

한 번에 하나의 가장 중요한 불확실성을 푼다. 다만 서로 독립적인 축이 동시에 똑같이 불명확하면 한 번의 호출에 최대 4개까지 묶어 물어도 된다.

### 텍스트 형식 (Codex 등)

Claude Code가 아닌 환경에서는 구조화된 질문 도구를 찾지 말고, 맨 아래 [텍스트 폴백 형식](#텍스트-폴백-형식)으로 질문한다.

## 스코프 평가 (세부 질문 전에)

세부 질문을 시작하기 전에 요청의 크기를 먼저 평가한다.

요청이 여러 독립 서브시스템에 걸쳐 있다면(예: "채팅, 파일 저장, 결제, 분석이 있는 플랫폼"), 즉시 이를 지적한다. 분해가 먼저 필요한 프로젝트의 세부사항을 다듬는 데 질문을 낭비하지 않는다.

하나의 작업 단위로 너무 크다면 하위 프로젝트로 분해를 돕는다: 독립적인 조각은 무엇인지, 서로 어떤 관계인지, 어떤 순서로 만들어야 하는지. 그 후 첫 번째 하위 프로젝트부터 일반 인터뷰 흐름을 진행한다. 각 하위 프로젝트는 자체적인 요구사항 정리, 계획, 구현 사이클을 가진다.

적절한 크기의 요청이면 바로 질문 축으로 넘어간다.

## 질문 축

아래 순서로 가장 불명확한 축 하나를 고른다.

- 목표
- 범위와 제외 범위
- 제약
- 완료 기준
- 기존 맥락과 영향 범위

코드베이스를 보면 답할 수 있는 질문은 사용자에게 묻지 말고 직접 확인한다.

## 진행 방식

질문 도구로 질문하고, 답변을 받으면 결정된 내용을 짧게 갱신한다.

아직 중요한 불확실성이 남았을 때만 다음 질문을 한다.

선택지가 도움이 되면 2~3개만 제시한다. 추천이 있으면 맨 앞 선택지로 두고 이유를 곁들인다.

## 텍스트 폴백 형식

구조화된 질문 도구가 없는 환경에서만 사용한다.

질문마다 아래 내용을 짧게 제시한다.

```md
현재 이해: {요청을 한 문장으로 요약}
막힌 결정: {가장 중요한 불확실성}
질문: {한 가지 질문}
```

선택지를 제시할 때는 아래 형식을 따른다.

```md
현재 이해: {요청을 한 문장으로 요약}
막힌 결정: {가장 중요한 불확실성}

질문: {한 가지 질문}

1. {선택지 A}

- {짧은 설명}

2. {선택지 B}

- {짧은 설명}

3. {선택지 C}

- {짧은 설명}

제 추천은 N번입니다. 왜냐하면 {짧은 이유}
다른 의도라면 직접 적어주셔도 됩니다.
```

## 종료 기준

다음이 정리되면 멈춘다.

- 달성하려는 목표
- 포함 범위와 제외 범위
- 지켜야 할 제약
- 완료 판단 기준
- 아직 남은 열린 질문

마지막에는 전체 대화록이 아니라 결정사항과 열린 질문만 요약한다.
