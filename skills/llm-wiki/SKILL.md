# /llm-wiki — LLM 지식 참조

## 목적

이 Skill은 Agent가 로컬에 존재하는 LLM Wiki 문서를 참조하고, 필요한 경우 문서 초안을 작성하는 방법을 정의한다.

LLM Wiki는 다음 정보를 찾기 위한 로컬 지식 저장소다.

- 프로젝트 도메인 지식
- 개인 개발 컨벤션
- 트러블슈팅 기록
- 재사용 가능한 프롬프트

## Wiki 위치 확인

`~/Documents/wiki`

## 언제 Wiki를 참조할 것인가

다음 상황에서는 LLM Wiki를 먼저 참조한다.

- 사용자가 "플러그인 호출", “위키에서 찾아봐”, “예전에 정리한 것 기준으로” 라고 말한 경우
- 작업이 과거 의사결정이나 프로젝트 맥락에 의존하는 경우
- 코드 작성/리뷰에 프로젝트 도메인 지식이 필요한 경우

## 읽는 순서

Wiki를 참조할 때는 아래 순서를 따른다.

1. `00_INDEX.md` 또는 `index.md`를 먼저 읽는다.
2. 관련 폴더와 문서명을 확인한다.
3. 필요한 키워드로 검색한다.
4. 관련 문서를 읽고 핵심만 요약한다.
5. 현재 작업에 적용한다.

## 답변 방식

Wiki를 참고한 경우 다음을 지킨다.

- 어떤 문서를 참고했는지 간단히 언급한다.
- 문서 내용을 그대로 길게 복사하지 않는다.
- 현재 작업에 필요한 내용만 요약한다.
- Wiki 내용과 현재 repo 코드가 충돌하면 충돌 사실을 알린다.
- 오래된 문서는 절대적인 기준으로 보지 않는다.
- 현재 repo 코드와 실제 구현을 더 신뢰한다.

## Wiki 작성이 필요한 경우

다음 경우에는 Wiki에 추가할 문서 초안을 작성한다.

- 프로젝트 맥락이 추가/변경된 경우
- 재사용 가능한 프롬프트나 워크플로우가 생긴 경우
- 아키텍처 의사결정이 발생한 경우
- 반복될 가능성이 있는 트러블슈팅을 해결한 경우

단, 중요한 컨벤션이나 의사결정 문서는 사용자 확인 없이 직접 확정하지 않는다.

## 문서 작성 형식

새 문서는 간결하게 작성한다.

권장 형식:

```md
# 제목

## Keywords

검색에 걸릴 주요 키워드

## Summary

짧은 요약

## Details

필요한 내용만 정리

## Related

- 관련 문서
- 관련 파일
```

## 주의사항

- Wiki를 맹신하지 않는다.
- 없는 히스토리를 지어내지 않는다.
- 임시 작업 메모를 영구 컨벤션 문서에 섞지 않는다.
- 너무 긴 문서를 만들지 않는다.
- 문서의 목적은 “Agent가 다시 잘 찾고 읽게 하는 것”이다.
